1. SQL (Schemas/Tables && Records/Tuples )
- Data uses Schemas: Structure is predefined.
- Relations!: Uses relational models to link data.
- Data is distributed across multiple tables: Normalized data storage.
- Scaling: Horizontal scaling is difficult/impossible; Vertical scaling is possible.
- Performance: Limitations for lots of (thousands) read & write queries per second.

2. NoSQL (Collections && Documents)
- Schema-less: Flexible data structure.
- No (or very few) Relations: Non-relational approach.
- Data is typically merged / nested in a few collections: Denormalized data storage.
- Scaling: Both horizontal and vertical scaling is possible.
- Performance: Great performance for mass read & write requests.
